# ТЗ: battery-soh-bench

Тулкит для студенческого соревнования по оценке SOH литий-ионной ячейки
по фрагменту зарядной кривой.

Версия 0.1 — черновик для обсуждения. Разделы, помеченные **[РЕШИТЬ]**,
требуют подтверждения до начала реализации.

---

## 1. Задача, которую обслуживает тулкит

По случайному фрагменту зарядной кривой фиксированной ширины по напряжению
предсказать нормированную остаточную ёмкость (SOH) ячейки на момент этого
цикла.

Обучение: CALCE, KIT NMC/C-SiO, Oxford.
Скрытый тест: Sandia (NCA + NMC; LFP — отдельная бонусная номинация).

Ключевые ограничения задачи, которые тулкит обязан обеспечивать
механически, а не договорённостью:

- номер цикла и история предыдущих циклов на вход **не подаются**;
- сплит по ячейкам, не по циклам;
- тестовые фрагменты детерминированы (фиксированный seed), одинаковы
  для всех команд и не перегенерируются.

## 4. Унифицированная схема данных

Два parquet-уровня. Целевую схему берём совместимой с форматом Battery
Archive там, где он что-то диктует, но не копируем его буквально.

### 4.1 `cells.parquet` — по одной строке на ячейку

| поле | тип | описание |
|---|---|---|
| `cell_id` | str | `{dataset}_{original_id}`, глобально уникален |
| `dataset` | enum | calce / kit / oxford / sandia |
| `chemistry` | enum | LCO / NMC / NCA / LFP / NMC_SiO |
| `form_factor` | enum | cylindrical_18650 / prismatic / pouch |
| `nominal_capacity_ah` | f64 | паспортная |
| `bol_capacity_ah` | f64 | измеренная в начале жизни, см. §5 |
| `temperature_setpoint_c` | f64 | уставка камеры |
| `charge_protocol` | str | свободный текст, например `CC-CV 0.5C to 4.2V, cutoff 0.05A` |
| `batch_id` | str \| null | если известна партия — заполнить |
| `notes` | str \| null | аномалии, найденные при разборе |

### 4.2 `cycles.parquet` — по одной строке на цикл

| поле | тип | описание |
|---|---|---|
| `cell_id` | str | |
| `cycle_index` | i32 | сквозной, с 1 |
| `capacity_ah` | f64 \| null | разрядная ёмкость цикла, если измерима |
| `is_reference` | bool | цикл является опорным измерением (RPT / check-up) |
| `soh` | f64 | целевая переменная, см. §5 |
| `soh_source` | enum | `measured` / `interpolated` |
| `soh_gap_cycles` | i32 | расстояние до ближайшего опорного цикла |

### 4.3 `timeseries/` — parquet, партиционирован по `cell_id`

| поле | тип |
|---|---|
| `cell_id` | str |
| `cycle_index` | i32 |
| `step_type` | enum: `chg_cc` / `chg_cv` / `dch` / `rest` |
| `t_s` | f64, от начала цикла |
| `voltage_v` | f64 |
| `current_a` | f64, **заряд положительный** |
| `temperature_c` | f64 \| null |
| `charge_ah` | f64, накопленный внутри шага |

Соглашения, обязательные к соблюдению во всех адаптерах:

- ток заряда положительный, разряда отрицательный;
- `charge_ah` считается интегрированием тока, а не берётся из исходника
  (в исходниках разные соглашения о сбросе счётчика);
- время в секундах от начала цикла, не абсолютное;
- пропуски — `null`, не нули и не -1.

### 4.4 Разметка `step_type`

Единственное место, где адаптеры имеют право расходиться в логике.
Определение CC/CV фазы заряда:

- `chg_cc`: ток > 0 и стабилен в пределах ±2% от медианы шага;
- `chg_cv`: ток > 0, напряжение стабильно в пределах ±5 мВ, ток падает.

**[РЕШИТЬ]** Пороги вынести в `benchmark.yaml` или зашить. Предлагаю
вынести — на KIT с разрешением 2 с они почти наверняка потребуют правки.

## 5. Целевая переменная — самая ответственная часть

`soh = capacity_ah(cycle) / bol_capacity_ah`

Правила:

1. **`bol_capacity_ah`** — ёмкость **этой ячейки**, измеренная на первом
   опорном цикле. Не паспортная. Не среднее по партии.
2. **Опорный цикл** — медленный полный разряд в рамках check-up / RPT.
   В каждом датасете определяется по-своему, см. §6.
3. Для неопорных циклов SOH получается **линейной интерполяцией**
   между соседними опорными, `soh_source = interpolated`.
4. Фрагменты, у которых `soh_gap_cycles` больше порога
   (**[РЕШИТЬ]**, предлагаю 60), из бенчмарка исключаются — шум разметки
   превысит полезный сигнал.
5. Экстраполяция за пределы последнего опорного цикла **запрещена**.

> Замечание для исполнителя: этот раздел нельзя реализовывать «по
> здравому смыслу». Каждый датасет требует явного решения, что считать
> опорным измерением, и это решение принимает владелец репозитория,
> а не агент.

### 5.1 Альтернатива: только опорные циклы — **[РЕШИТЬ], рекомендую**

Во всех четырёх наборах опорные измерения — это отдельные медленные
циклы с собственным профилем заряда:

| датасет | опорный цикл | заряд |
|---|---|---|
| Oxford | характеризация каждые 100 циклов | CC C/18.5 |
| Sandia | capacity check, 3 цикла 0–100% SOC | CC-CV 0.5C |
| CALCE CS2 | заряд одинаков во всех циклах | CC-CV 0.5C |
| KIT | check-up | по описанию набора |

Если строить фрагменты **только из опорных циклов**, получаем сразу три
выигрыша:

1. `soh` всегда `measured`, интерполяция §5 п.3 не нужна вовсе;
2. протокол заряда внутри каждого датасета постоянен — исчезает
   конфаунд «форма кривой меняется от режима, а не от старения»;
3. у Sandia это критично: там заряд зависит от режима DOD (40–60% SOC —
   CC по ёмкостным лимитам, 20–80% — CC по напряжению, 0–100% — CC-CV),
   и без ограничения на capacity check тест смешивает перенос по химии
   с переносом по протоколу заряда.

Цена — меньше фрагментов: у Oxford порядка 500 кривых на 8 ячеек,
у Sandia — по числу capacity check на 86 ячеек. Для CALCE и KIT ограничение
почти ничего не стоит.

Предлагаю: **основной режим — только опорные циклы**, а расширение на
рабочие циклы с интерполированным SOH сделать опциональным флагом
конфига для команд, которым не хватит данных.

## 6. Адаптеры

Общий контракт (`ingest/base.py`):

```python
class DatasetAdapter(Protocol):
    name: str

    def discover(self, raw_dir: Path) -> list[CellSource]: ...
    def load_cell(self, src: CellSource) -> CellBundle: ...
    def mark_reference_cycles(self, bundle: CellBundle) -> CellBundle: ...
```

`CellBundle` содержит три фрейма по схеме §4. Весь датасет-специфичный
беспорядок живёт внутри адаптера и наружу не протекает.

### 6.1 Oxford — делать первым

Самый маленький и чистый. 8 pouch-ячеек LCO, камера 40 °C, заряд CC-CV,
разряд по ездовому профилю Artemis, характеризация каждые 100 циклов.

Опорный цикл = цикл характеризации. Определяется по профилю разряда:
медленный CC вместо драйв-цикла.

Служит сквозной проверкой всего пайплайна. Пока Oxford не проходит
end-to-end, остальные адаптеры не начинать.

### 6.2 CALCE

Основной обучающий набор. Серия CS2: призматические LCO 1.1 А·ч, заряд
единый CC-CV 0.5C до 4.2 В с отсечкой 0.05 А, разряд варьируется по
шести типам. Именно постоянство заряда делает набор пригодным.

Сложности: смесь `.mat` и `.xlsx`, разрозненная документация, дыры
в отдельных сериях.

**[РЕШИТЬ]** Брать ли помимо CS2 другие серии CALCE. Аргумент за:
в обучении иначе две трети LCO, а тест содержит NCA/NMC/LFP. Добавление
LFP-серии CALCE заметно смягчит §9.

### 6.3 KIT NMC/C-SiO

228 ячеек, 76 режимов, по три ячейки на условие, четыре температуры
от 0 до 40 °C, календарное и циклическое старение плюс ездовые профили.
Сырые логи с разрешением 2 с, свыше 3 млрд точек.

Два требования:

- **потоковый разбор**, датасет целиком в память не помещается;
- прореживание до целевого разрешения на этапе ingest
  (**[РЕШИТЬ]**, предлагаю 10 с), с сохранением исходного разрешения
  внутри CC-фазы заряда — там оно нам и нужно.

Опорные измерения берутся из результатов check-up, они в датасете есть
в готовом виде. Это единственный набор, где целевая переменная
определяется без наших допущений.

**[РЕШИТЬ]** Календарное старение — включать или отфильтровать. Склоняюсь
отфильтровать: задача про циклическую деградацию.

### 6.4 Sandia — тестовый

18650 трёх химий: LFP (A123), NCA (Panasonic), NMC (LG Chem), циклирование
до 80% ёмкости, варьируются температура, глубина разряда и ток разряда.
Есть на Battery Archive в стандартном формате — адаптер должен быть
самым простым.

Обрабатывается **тем же кодом**, что и обучающие. Никаких ветвлений
«если тест» в пайплайне: расхождение обработки между train и test —
классический источник тихого провала.

## 7. Генератор фрагментов

`fragments.py`, единственная точка порождения входов модели.

Параметры (`benchmark.yaml`):

```yaml
fragment:
  delta_v: 0.2          # ширина окна, В
  n_points: 128         # точек после ресемплинга
  phase: chg_cc         # только CC-фаза заряда
  v_normalization: per_cell_range   # absolute | per_cell_range
  channels: [q_norm, current, temperature]
  min_points_in_window: 20          # иначе фрагмент отбрасывается
  seed: 20260901
```

Алгоритм:

1. Взять CC-фазу заряда цикла.
2. Выбрать начало окна `v_start` равномерно из допустимого диапазона
   так, чтобы `[v_start, v_start + delta_v]` целиком лежало внутри фазы.
3. Интерполировать `Q(V)` на равномерную сетку из `n_points`.
4. Нормировать `Q` на `bol_capacity_ah` ячейки.
5. Приложить каналы тока и температуры на той же сетке.

Выход — `fragments.parquet`:

| поле | описание |
|---|---|
| `fragment_id` | детерминированный хеш от (cell_id, cycle_index, v_start, seed) |
| `cell_id`, `cycle_index` | **только в train/val; в тестовом файле участников отсутствуют** |
| `v_start`, `v_end` | границы окна |
| `q_norm` | list[f64], n_points |
| `current`, `temperature` | list[f64], n_points |
| `soh` | целевая; **в тестовом файле участников отсутствует** |

Два режима работы:

- `fixed` — детерминированная генерация по seed, используется для val
  и test. Результат коммитится как артефакт и не перегенерируется;
- `sampling` — случайная генерация на лету, для аугментации на обучении.
  Доступна участникам через `dataset.py`.

**Про `v_normalization`:** см. §9. Значение по умолчанию требует
подтверждения — оно определяет, осмыслен ли тест на LFP вообще.

## 8. Сплиты

- Единица разбиения — **ячейка**. При наличии `batch_id` — партия.
- Списки ID лежат в `splits/*.txt` как простые текстовые файлы,
  коммитятся, генерируются один раз.
- `train` / `val` — из CALCE, KIT, Oxford. `test` — Sandia целиком.
- В `val` попадают ячейки, не встречающиеся в `train`, включая по
  возможности отдельные режимы целиком — чтобы val хоть немного
  предсказывал поведение на test.

Функция проверки `assert_no_cell_leakage()` вызывается в CI и падает
при пересечении.

## 9. Обработка расхождения по химии

Обучение — преимущественно LCO плюс NMC/C-SiO. Тест — NCA, NMC, LFP.

С NCA и NMC перенос осмыслен. LFP — качественно другой сигнал: плоское
зарядное плато и верхняя граница около 3.6 В против 4.2 В. При
`v_normalization: absolute` окно 3.9–4.1 В на LFP-ячейке не существует
физически, и генератор выдаст пустоту.

Решение, принятое в этом ТЗ:

- **основной тест** — только NCA и NMC;
- **LFP** — отдельная бонусная номинация, считается тем же `eval.py`
  с флагом `--hard-mode`;
- `v_normalization: per_cell_range` по умолчанию, чтобы окна вообще
  существовали для всех химий.

**[РЕШИТЬ]** Альтернатива — добавить LFP в обучение из CALCE и вернуть
LFP в основной тест. Честнее, дороже по подготовке.

## 10. Метрики и `eval.py`

Основные:

- `MAE` в процентных пунктах SOH;
- `P95` абсолютной ошибки — худший случай важнее среднего для BMS;
- разбивка по химии, температуре и по децилям SOH (интересует поведение
  на сильно состаренных ячейках, их всегда меньше).

Для номинации «калибровка»:

- покрытие 90% интервала (эмпирическая доля попаданий);
- средняя ширина интервала.

Для номинации «экономность»:

- размер модели в байтах — считается тулкитом по файлу сабмита команды;
- минимальная `delta_v`, при которой команда удерживает заявленную
  точность — прогоняется `eval.py` по сетке `delta_v`
  (**[РЕШИТЬ]**, предлагаю 0.05 / 0.1 / 0.15 / 0.2 В).

Вывод — одна таблица в stdout и `results.json`.

## 11. Формат сабмита и валидатор

CSV или parquet:

```
fragment_id,soh_pred,soh_lo,soh_hi
```

`soh_lo` / `soh_hi` — границы 90% интервала, опциональны; без них
команда не участвует в номинации «калибровка», но участвует в остальных.

`validate_submission.py` проверяет:

- полнота: все `fragment_id` теста присутствуют, лишних нет;
- диапазон: `soh_pred` в (0, 1.2];
- согласованность: `soh_lo <= soh_pred <= soh_hi`;
- отсутствие NaN.

Сообщения об ошибках — с указанием конкретных строк. Без этого первые
две недели уйдут на переписку про форматы.

## 12. Бейзлайны и опорные числа

Не один бейзлайн, а набор. Задача — задать рамку, внутри которой
читается любой результат команды.

### 12.1 Четыре числа, публикуемые в README до старта

| число | что это | как получается |
|---|---|---|
| **Пол** | предсказание константы | `baseline --model constant` |
| **Проба на утечку** | модель без доступа к кривой | `baseline --model probe` |
| **Бейзлайн** | то, что надо побить | `baseline --model elastic_net` |
| **Потолок** | шумовой пол данных | §12.4 |

Без «пола» результат команды нечитаем: на тесте со сменой химии
плохо перенёсшаяся модель легко оказывается хуже предсказания среднего,
и это надо видеть сразу, а не выяснять на защите.

### 12.2 `--model constant`

Предсказывает среднее `soh` по train. Десять строк кода. Считается
отдельно по химиям теста — иначе число вводит в заблуждение.

### 12.3 `--model probe` — проверка генератора фрагментов

Модель, которой **не дают саму кривую**. На вход только метаданные
фрагмента: `v_start`, `v_end`, средняя температура, средний ток.

Ожидаемый результат — примерно на уровне «пола». Если проба заметно
лучше, значит **генератор фрагментов протекает**, и вся задача
испорчена.

Конкретный механизм утечки, которого стоит опасаться при
`v_normalization: per_cell_range` (§7): у состаренной ячейки рабочий
диапазон напряжения может отличаться от свежей, а значит допустимый
диапазон `v_start` коррелирует с SOH. Тогда модель выучит положение
окна вместо формы кривой и покажет прекрасные цифры, не решая задачу.

Проба гоняется в CI на каждое изменение `fragments.py`. Порог падения
теста (**[РЕШИТЬ]**, предлагаю: проба не лучше пола более чем на 15%)
зашивается в тест.

### 12.4 Потолок — шумовой пол

Разброс SOH между номинально одинаковыми ячейками при одинаковой
наработке. Это точность, лучше которой не может быть ни одна модель.

Считается по репликам:

- Sandia — не менее 2 ячеек на каждую комбинацию температуры, DOD
  и тока разряда;
- KIT — 3 ячейки на условие;
- при нехватке — HNEI (§17.6), там внутрипартийный разброс
  и есть предмет исследования.

Считать **на тестовом наборе**, это даёт прямо интерпретируемое число.
Вынести в `bsb noise-floor`.

> Число нужно не только студентам. Аргумент «требовать точность выше
> разброса между ячейками физически невозможно» — рабочий довод
> в разговоре с заказчиком о целевых метриках.

### 12.5 `--model elastic_net` — основной бейзлайн

Признаки из окна:

- `dQ/dV` на сетке, сглаженное фильтром Савицкого-Голея;
- дисперсия, среднее, минимум и максимум `dQ/dV` внутри окна;
- `v_start`, `v_end`, ширина окна;
- средний и максимальный ток окна — **обязательно**: заряд у Oxford
  C/18.5, у CALCE и Sandia 0.5C (§17.3), без этого канала модель
  спутает сдвиг по току со старением;
- средняя температура окна;
- интеграл `q_norm` по окну.

Стандартизация признаков — глобальная, по train. Понормировать
на «первый цикл этой ячейки» нельзя: истории циклов на входе нет
по условию задачи (§1).

Требование: бейзлайн должен быть **сильным**. Бюджет на подбор —
фаза 8 плана §15, и это моя работа, не агента. Целевой ориентир —
единицы процентных пунктов MAE на val; итоговое число фиксируется
после первого честного прогона и попадает в README.

### 12.6 Запуск

```
bsb baseline --model elastic_net --config configs/benchmark.yaml
bsb noise-floor
```

Обе команды печатают число и пишут в `results.json`. Первая — за время
жизни чашки кофе, иначе ей не будут пользоваться.

## 14. Тесты

Минимальный набор, без которого не принимать:

- round-trip: синтетическая ячейка с известной ёмкостью проходит
  ingest → labels → fragments и восстанавливается;
- детерминизм: две генерации фрагментов с одним seed побитово совпадают;
- отсутствие утечки ячеек между сплитами;
- валидатор ловит каждый из четырёх классов ошибок §11;
- на каждый адаптер — smoke-тест на одной реальной ячейке,
  зафиксированной в репозитории;
- **проба на утечку** (§12.3): `probe` не должна быть заметно
  лучше `constant`. Гоняется на каждое изменение `fragments.py`.

**Приёмка адаптера — глазами, а не тестом.** Для каждого датасета
строится график `soh` по циклам для 3–5 ячеек. Кривая должна
монотонно убывать без ступенек и выбросов. Ступенька означает ошибку
в определении опорных циклов, и никакой юнит-тест её не поймает.

## 17. Источники данных

### 17.1 CALCE — обучение

- Точка входа: https://calce.umd.edu/battery-data
- Также: https://calce.umd.edu/data и https://calce.umd.edu/data%20II

Серия **CS2** — 15 призматических LCO на 1.1 А·ч при комнатной
температуре. Заряд одинаков у всех ячеек: CC-CV 0.5C до 4.2 В с отсечкой
по току 0.05 А; отсечка разряда, если не указано иное, 2.7 В. Ячейки
разбиты на шесть типов по профилю разряда: типы 1 и 2 — CC-разряд 0.5C
и 1C, тип 3 — переключение между шестью заранее заданными токами,
типы 4–6 — разные отсечки по напряжению для имитации частичных
циклов. Есть также серия **CX2** — тоже призматические LCO.

Формат: коллекция Excel-файлов на ячейку, имена по датам тестирования.
**Исключение:** CS2_8 и CS2_21 тестировались на CADEX вместо Arbin
и лежат в `.txt`. Адаптер должен обрабатывать оба случая.

### 17.2 KIT NMC/C-SiO — обучение

Публикация: Luh & Blank, *Scientific Data*, DOI `10.1038/s41597-024-03831-x`
(https://www.nature.com/articles/s41597-024-03831-x). Организация — KIT,
Institute for Data Processing and Electronics, **не TUM**.

Данные (актуальные версии по DOI):

- результаты check-up: `10.35097/1969`
- сырые логи: `10.35097/kww7jv8ajuvchcah`
- исправленный `cell_eisv2_fixed.zip` (в исходной публикации файл
  `cell_eisv2.zip` неполон): `10.35097/krk531nmj4bsshha`

**Готовые Python-скрипты чтения, обработки и визуализации:**
https://github.com/energystatusdata/bat-age-data-scripts/ —
начинать адаптер с них, а не с нуля.

### 17.3 Oxford — обучение / отладка

- Запись: https://ora.ox.ac.uk/objects/uuid:03ba4b01-cfed-46d3-9b1a-7d4a7bdf6fac
- Лицензия: Open Database License (ODbL 1.0), содержимое — DbCL 1.0
- Цитировать DOI набора плюс диссертацию: Christoph R. Birkl,
  "Diagnosis and Prognosis of Degradation in Lithium-Ion Batteries",
  PhD thesis, University of Oxford, 2017

**Важно для адаптера.** В наборе два файла:

- `ExampleDCC1.mat` — один первый цикл заряд-разряд целиком;
- `OxfordBatteryDegradationDataset_1.mat` (262 МБ) — **только результаты
  характеризационных тестов**, снятых каждые 100 циклов до конца жизни.

То есть кривых рабочих циклов в наборе нет. Рабочее циклирование шло
CC-зарядом 2C до 4.2 В с разрядом по профилю Artemis urban в диапазоне
4.2–2.7 В, а характеризация — полный CC заряд-разряд на C/18.5 (40 мА).

Следствие: **все фрагменты Oxford будут с C/18.5**, тогда как у CALCE
и Sandia заряд 0.5C. Это сдвиг по току между обучением и тестом.
Канал тока во входе (§7) обязателен именно поэтому.

### 17.4 Sandia (SNL) — скрытый тест

- Battery Archive, ключевое слово `SNL`: https://www.batteryarchive.org/
- Описание исследования: https://batteryarchive.org/snl_study.html
- Сводка по всем наборам: https://www.batteryarchive.org/study_summaries.html
- Лицензия: double attribution — цитировать и Battery Archive,
  и исходную публикацию (Preger et al., «Degradation of Commercial
  Lithium-ion Cells as a Function of Chemistry and Cycling Conditions»)

Состав: 86 ячеек 18650 — 30 LFP (A123 APR18650M1A, 1.1 А·ч),
24 NCA (Panasonic NCR18650B, 3.2 А·ч), 32 NMC (LG Chem 18650HG2, 3 А·ч).
Циклирование до 80% ёмкости. Варьируются температура, глубина разряда
и ток разряда.

Критично для §5.1 и §9:

- **заряд у всех ячеек 0.5C** по рекомендации производителя;
- capacity check — три цикла заряд-разряд 0–100% SOC на 0.5C,
  в начале и в конце каждого раунда циклирования;
- протокол заряда зависит от режима DOD: 40–60% SOC — CC по ёмкостным
  лимитам, 20–80% SOC — CC по напряжению, 0–100% SOC — CC-CV с отсечкой
  по 30 минутам или спаду тока до 0.05 А;
- диапазоны напряжения при 100% DOD: **LFP 2–3.6 В**, NCA 2.5–4.2 В,
  NMC 2–4.2 В. Это и есть количественное основание §9.

### 17.5 Готовые инструменты — посмотреть до написания адаптеров

- **BatteryML** (arXiv 2310.14714) — открытая платформа для ML на
  деградации батарей, содержит загрузчики и препроцессоры для CALCE,
  SNL, MATR, HUST. Стоит потратить день на оценку: если её схема
  подходит, фазы 4 и 6 плана §15 сокращаются в разы.
- **bat-age-data-scripts** — см. §17.2, для KIT.
- **BEEP** — импорт и извлечение признаков из данных циклирования.
- **Battery Archive** — общий формат, который мы берём за ориентир §4.

### 17.6 Не используем, но пусть будет под рукой

- **MATR / Severson** (`10.1038/s41560-019-0356-8`) — для RUL-бейзлайна
  основного проекта, не для этого бенчмарка. Обоснование обсуждалось
  отдельно: там варьируется протокол заряда, то есть наш вход.
- **NASA PCoE** — только как sanity check.
- **HNEI** (на Battery Archive) — 51 ячейка NMC-LCO 18650, исследование
  именно внутрипартийного разброса. Полезно для оценки шумового пола
  (§18), если понадобится третья точка.
